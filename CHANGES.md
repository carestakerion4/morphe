# Что изменено и как это применить

## Порядок применения

1. Сделай бэкап БД (или прогоняй на staging-проекте Supabase).
2. В SQL Editor выполни `supabase/000_preflight.sql` (только чтение) и посмотри результаты:
   нестандартные политики RLS, старые сигнатуры функций, «грязные» ники.
3. Выполни `supabase/001_eidos_hardening.sql` **и сразу задеплой этот фронтенд.**
   Старый клиент после миграции перестаёт работать: он пишет `views`/`is_banned` напрямую,
   а теперь это запрещено на уровне БД.
4. Проверь защиту (блок «ПРОВЕРКА ПОСЛЕ ПРИМЕНЕНИЯ» в конце 001): обычный аккаунт не должен
   мочь выставить себе `is_admin`.
5. Превью ссылок: выбери адаптер под свой хостинг — `edge/README.md`.
6. `npm test` — 36 тестов, без сети и без браузера.

Свой `.env` оставь как есть (в архив я его не клал). Теперь он в `.gitignore`; если он уже
попал в git — `git rm --cached .env`. Ключ там publishable, ротировать его не нужно.

## Безопасность

- Привилегированные колонки (`is_admin`, `is_banned`, `views`, `link_clicks`) нельзя писать с клиента:
  column-level GRANT. Админские действия — RPC с проверкой `is_admin()` на сервере.
- Ссылки/картинки профиля проходят проверку схемы, внешние `<img>` — `referrerPolicy="no-referrer"`.
- Шрифт/цвета из `theme_config` не попадают в стиль без проверки.
- Подсчёт просмотров: не чаще раза в сутки с одного посетителя (опционально, внутри 001).
- Хранилище: загрузка и удаление только в свою папку, JPEG ≤ 2 МБ.
- Заголовки безопасности (`public/_headers`, `vercel.json`), `.env` в `.gitignore`.

## Что НЕ проверено

- **SQL не запускался.** Postgres здесь не было. Файл написан по коду приложения; параметры RPC и
  список колонок в GRANT автоматически сверены с клиентом, но на твоей базе он не исполнялся.
- Адаптеры превью (`edge/adapters/*`) не запускались на живых платформах; ядро (`edge/og.js`) покрыто тестами.
- Сборка (`vite build`) и `oxlint` не запускались (нет Linux-бинарников). Вручную проверен порядок хуков.
- Логика входа/регистрации/сохранения вынесена в тестируемые функции и проверена, но сами
  React-эффекты в живом браузере не гонялись.

## Что не сделано (осознанно)

- Сброс пароля («Forgot password») — это новая функция, а не исправление.
- Данные забаненного профиля по-прежнему отдаёт API (UI их скрывает). Чтобы закрыть, нужен
  view/RPC вместо прямого `select`.
- `is_admin` по-прежнему читается через API (лучше вынести в отдельную таблицу).
- Клики не ограничены по частоте (в отличие от просмотров).
- QR-код в дашборде по-прежнему строится внешним `api.qrserver.com` (URL профиля уходит третьей стороне).
- Смена ника не оставляет редирект; освободившийся ник можно сразу занять.
- Нет SSR: превью для ботов — обходное решение, а не полноценный SSR.
